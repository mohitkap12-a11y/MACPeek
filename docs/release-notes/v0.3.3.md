# MacPeek 0.3.3

Reach your Mac from anywhere with MacPeek Remote, add a Mac to your account in one step, and manage Docker images remotely. Still free, open source (MIT), no telemetry, and MacPeek itself needs no account. Apple silicon and Intel, macOS 13 or later.

> **Heads-up:** pairing with a one-time code is gone. Consoles paired with a code in 0.3.0–0.3.2 stop connecting until you add the Mac to your account (Settings > Remote management > **Add to my account**).

## Highlights
- **Add to my account**: the one way to add a Mac to MacPeek Remote. Sign in in the browser from MacPeek, approve the Mac in MacPeek Remote on your main Mac, and it joins your account.
- **Allow from anywhere**: your account's devices reach the Mac from any network through MacPeek's end-to-end encrypted relay, without opening a port.
- **Container images, remotely**: list the Docker engine's images, delete an image or tag, and start a container from an image.
- **Meet MacPeek Remote**: a launcher row and a short window with pictures of the console.
- **More reliable connections**: the relay and the local-network listener recover by themselves after Wi-Fi drops or a failure.

## MacPeek Remote introduction
- A row at the bottom of the launcher opens a window with four pictures of the console and a **Get MacPeek Remote** button that opens remote.macpeekapp.com.
- The window opens by itself once after this update. **Remind Me Later** (or closing it) brings it back in a week; **Never show this again** or following the link stops that.
- The pictures are in the app: nothing is fetched or sent.

## Remote management (Settings > Remote management)
Off by default. While off, nothing listens or connects.

- **Add to my account**: sign in to your MacPeek Remote account in the browser from MacPeek, then approve the Mac in MacPeek Remote on your main Mac. The Mac joins with View and act and **Allow from anywhere** on, and says so. Actions still need **Allow actions**.
- **Allow from anywhere**: while on, the Mac keeps one outbound connection to the relay and serves each of the account's consoles through it, with the same handshake, per-request checks and **Allow actions** as on the local network. Off by default, available only while the Mac is in an account, and turning it on or off is recorded in the activity log. Turning it off, turning Remote management off, or leaving the account closes the connection at once.
- **Pairing with a code removed**: the one-time code, the four words, consoles paired one by one, "Move this Mac to your account" and "Undo move" are gone. A Mac is reachable only by the devices of the account it was added to; a Mac in no account refuses every console.
- **Recovers by itself**: the relay connection is checked every 15 seconds and replaced after 40 seconds of silence, and reconnects as soon as the network comes back (previously a Wi-Fi toggle left it stuck until MacPeek was relaunched). The local-network listener restarts after a failure, so consoles on the same network find the Mac again.
- **New for consoles**:
  - `containers.images`: the Docker engine's images and which containers use each.
  - `images.remove` (action): `docker image rm`, never forced; Docker refuses an image a container uses.
  - `containers.run` (action): `docker run --detach --pull never` with only an optional name and published ports, bound to `127.0.0.1` unless you choose to expose them to the network. No volumes, environment, privileges or command override; pulling and loading images are not offered.
  - `disk.io`: bytes read and written by the drive behind each volume, so MacPeek Remote can show an external drive's own read and write speed.
  - GPUPeek replies now carry Metal's GPU facts (family, memory the GPU may use), so the console can show GPU memory as a share of what the GPU may use.
  - Actions are gated by **Allow actions** like the others. Protocol: `docs/remote.md`.

## Existing utilities
- **USBPeek**: Bluetooth devices whose battery level system_profiler leaves out (macOS's Bluetooth menu still shows one) now get it from the I/O registry. A name shared by two connected devices is not filled in this way, so one device's level is never shown on another.

## Changelog (v0.3.2 -> v0.3.3)

### Added
- MacPeek Remote introduction (launcher row and window)
- Remote management: Add to my account
- Remote management: Allow from anywhere (end-to-end encrypted relay)
- Remote requests for Docker images: `containers.images`, `images.remove`, `containers.run`
- Remote `disk.io` read with per-drive read and write counters

### Changed
- Remote GPUPeek replies include Metal's GPU family and the memory the GPU may use (re-read at most once a minute)
- `scripts/build-app.sh` takes `MACPEEK_ENV=staging` or `MACPEEK_API_URL` and writes the service address into `Info.plist` (production by default), refusing addresses that would corrupt it
- CI: job timeouts, superseded PR runs cancelled, docs-only changes skip CI

### Fixed
- Relay reconnects after Wi-Fi goes off and on; the local-network listener restarts after a failure
- USBPeek and the remote agent read Bluetooth battery levels from the I/O registry when system_profiler has none
- `disk.io` finds a volume's drive through its parent slice when the exact media is not registered
- `build-app.sh` no longer reports a false "rpath to Contents/Frameworks is missing" error

### Removed
- Remote pairing with a code, consoles paired one by one, "Move this Mac to your account" and "Undo move"

## Upgrading
- MacPeek offers the update itself (Settings > Updates > Check for Updates…), or download **MacPeek.dmg** below.
- No new permissions or entitlements.
- **Consoles paired with a code stop connecting.** Use **Add to my account** in Settings > Remote management to reach the Mac from MacPeek Remote again.
- Remote management and Allow from anywhere stay off unless you turn them on.
