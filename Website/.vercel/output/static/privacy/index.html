MacPeek is private by design

MacPeek does not send process, port, display, network or any other system information to a server.

  • No account. Nothing to sign in to.
  • No telemetry or analytics in the app.
  • No cloud service required or used: no update pings, no crash reporting.
  • No network use in the background. The only traffic is a check you start yourself: NetPeek pings your router and DNS servers, and DNSPeek looks up a name you type. Both run only when you press the button.
  • Local operation. Data is held in memory to draw the screen and is not written to disk. The only thing stored is your preferences (which utilities are on, refresh interval, toggles) in macOS user defaults.
  • Open source. Verify it yourself.

What each utility reads

Utilities marked Coming soon are not in the current release; this is what they are planned to read, and the list will be re-checked against the code before it ships.

UtilityReads (locally)Access needed
PortPeek Listening sockets and the processes that own them, for your user account (via lsof) None to view. You can terminate only processes your user owns.
DisplayPeek Display properties from macOS (via system_profiler), only while DisplayPeek is open None.
USBPeek USB devices from the I/O registry (ioreg) and Thunderbolt port status (system_profiler), only while USBPeek is open None.
NetPeek Network configuration (route, scutil, networksetup) and Wi-Fi details (system_profiler) while NetPeek is open; pings to your router and DNS servers only when you press Run checks None. macOS hides the Wi-Fi network name from apps without Location access, and MacPeek does not request it.
BatteryPeek (coming soon) Battery and power-source information from macOS power services None.
SleepPeek Power-management assertions and settings (pmset); the sleep/wake log only when you ask for it None.
FileLockPeek Open files of processes owned by your user (via lsof), only for the path you choose, only when you scan None to scan. Other users’ processes are not listed, and you can terminate only processes your user owns.
ProcessPeek The process list (ps); a process’s command line and listening ports only when you open it None to inspect. Some details are unavailable for other users’ processes, and you can terminate only processes your user owns.
DiskPeek Per-process disk I/O counters (libproc) for processes your user can inspect, only while DiskPeek is open None. Other users’ processes are not shown.
EnvPeek MacPeek’s own environment and, where macOS permits, the environment of one process whose PID you enter None. Values are shown on screen only and never logged.
DNSPeek The system resolver configuration (scutil --dns); DNS lookups only when you press Run lookup None.

The two utilities that touch the network. NetPeek sends three pings to your router and to up to three of your DNS servers when you press Run checks. DNSPeek resolves the name you type, and asks each of your DNS servers for it, when you press Run lookup. Your DNS servers are often outside your home network (a public resolver or your ISP), so those requests do leave it. They carry no information about your Mac beyond what any lookup or ping contains, nothing is stored, and nothing runs when you do not ask.

MacPeek never asks for administrator rights and never bypasses macOS security controls.

This website

The site is static. It sets no cookies and loads no third-party scripts. The only thing it stores in your browser is your light/dark theme choice, locally. If privacy-friendly analytics are ever added, they will be documented here first.
