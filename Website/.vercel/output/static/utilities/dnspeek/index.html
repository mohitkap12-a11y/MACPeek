DNSPeek: Inspect DNS configuration and resolver behavior.

Which DNS servers is my Mac using, and do they respond?

DNSPeek is built and part of MacPeek's source. The first signed download has not been published yet; see Download for how to build it today.

The problem

Pages hang or a domain will not resolve. Which DNS servers is your Mac actually asking, and are they answering?

The solution

DNSPeek shows the DNS servers macOS uses for ordinary lookups, the interface and reachability behind them, search domains and the other resolvers (per-domain and multicast). Press Run lookup to resolve a name through macOS and to ask each server directly. It is read-only and never changes DNS settings.

Features

  • The DNS servers in use, in order, with their interface and reachability as macOS reports it
  • Search domains, per-domain resolvers, and the multicast (.local) and scoped resolvers explained
  • Run lookup: resolve a name the way apps do, then ask each server directly and see who answers, how fast and with what status
  • Only the name you type is ever queried, only when you press the button
  • Read-only: it never changes DNS settings
  • Copy the configuration for a support thread

How it works

  1. Open DNSPeek from the launcher.
  2. Read the DNS servers in use.
  3. Press Run lookup to test a domain against your resolver and each server.

Installation

DNSPeek is part of MacPeek. Install MacPeek, open Manage utilities and make sure DNSPeek is switched on (it is on by default). There is nothing separate to download.

Privacy

What DNSPeek reads:

  • The system resolver configuration (scutil --dns); DNS lookups only when you press Run lookup

Access it needs: None.

Nothing about your Mac is sent to any server, and there is no account and no telemetry. DNSPeek makes network requests only when you ask it to run a check. The name you type is sent to your Mac's DNS servers, which are often outside your home network (a public resolver or your ISP). Read the full privacy statement.
